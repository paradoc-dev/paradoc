# Changelog

All notable changes to Paradoc. Packages are versioned in lockstep.

## [Unreleased]

### Fixed

- `@paradoc/react`: `renderPdf` on the default Takumi adapter renders a preview's page plan when the plan carries captured fonts, and embeds them. It used to throw `UnsupportedApplicationTypographyError` for any plan with font resources or captured CSS, and the preview captures every stylesheet rule on the page, so a real app page never rendered on the default engine. Explicit `fonts` embed the same way. Takumi ignores the page CSS a plan captures, because it checks each class against its own vocabulary; it still throws `UnsupportedApplicationTypographyError` for `applicationCss` the caller passes. `paradoc dev` sends the plan's fonts with the PDF request instead of dropping them.
- CLI: the global config no longer wipes itself. `paradoc configure`, `paradoc reset`, and telemetry wrote `telemetry`, `anonymousId`, and the documented `security` key, which the config schema rejected; the next command then read the whole file as empty, and the next save deleted saved registries and their auth headers. The schema now owns these keys, the CLI uses the schema's `GlobalConfig` type, and every save is validated first. A missing `~/.paradoc/config.json` still means no settings; invalid JSON or a key or value the schema does not accept stops the command with an error that names the file and each bad key, and the file is not changed. `telemetry.enabled: false` turns telemetry off as documented, and a config that cannot be read also keeps telemetry off. `paradoc configure` keeps the settings it does not ask about, such as `security` and `cache.directory`.
- `@paradoc/core`: rendering a bundle nested in another bundle keeps every part of the inner bundle. `RuntimeBundle.render()` kept only the first inner part, under the parent's content key, and dropped the rest without an error. Each inner part is now keyed as a folder under the parent's key, such as `nested/docA` with the file `nested/docA.pdf`, and deeper nesting composes (`outer/inner/docA`). `assemble()` and `assembleBundle()` take a draft bundle as a content entry (`BundleAssemblyEntry`, exported) and name its parts the same way. A nested bundle that renders no parts fails in both.
- `@paradoc/render`: `extractFieldsFromPdf` and `locate` throw `UnknownMarkerError` when a marker's field type is not signature or initials, naming the page, signer, and field type code of each. Such a marker was read as a signature, so a damaged or newer marker could resolve a signature slot to a box the document never declared. `UnknownMarkerError` is exported from `@paradoc/render/pdf` and `@paradoc/sdk`.
- `@paradoc/ai-tools`: `get_fill_state` returns each rule error and warning as `{ rule_id, message }`, not a bare message string, so an agent can tell which rule failed. When a form's logic cannot be evaluated, the evaluation issues come back in `errors` with code `logic_unresolved` and the rule arrays stay empty. The `ai-sdk`, `tanstack-ai`, and `mastra` tools carry the same shape.
- `@paradoc/core`: `captureSignature`, `captureInitials`, `captureCapacity`, and `capturePrintedName` check the whole signing slot, not only the signer. They throw, naming the value, when the role is not declared, the party is not filled for that role, or the signer is not a signatory for that party. On a sealed form, the location must also be a `signatureMap` field for that signer and of that capture type.
- `@paradoc/sdk`: `hostedSealAdapter` throws `HostedConversionError`, with the HTTP `status` and the first 200 characters of the body, when the conversion API fails or answers with a body that is not JSON or not a PDF result. It no longer throws a bare `SyntaxError`. A new `signal` option cancels in-flight conversion requests, for example `signal: AbortSignal.timeout(30_000)`. Documents are base64-encoded with `Uint8Array.prototype.toBase64` where the runtime has it, and otherwise in chunks, without building one string the size of the document.
- `@paradoc/render`: the `@paradoc/types` peer range follows the release version, so a fresh `npm install` of a lockstep release resolves without `--legacy-peer-deps`.
- `@paradoc/render`: text layers escape values by their MIME type. `text/plain` and `text/markdown` print values as written, so `O'Brien` and `Smith & Sons` no longer come out as `O&#x27;Brien` and `Smith &amp; Sons`; `text/html` still escapes. `renderText` takes `mimeType` for the same choice and prints raw values without it. HTML signing marks escape the role, party, signer, and location attributes and the image, alt text, and class of a captured mark, and a captured Markdown mark escapes its alt text and image address, so a crafted value cannot add tags, attributes, or links.
- `@paradoc/essentials` and the bundled artifacts: text limits now fit their PDF boxes, so ordinary answers no longer fail to fill. Bank names are limited to 45 characters and account holder names to 45; other ACH, I-9, W-9, and HIPAA text limits are set to what their boxes hold. The ACH bank account information form takes the organization's domicile state as a two-letter code.
- `@paradoc/core`: a computed value whose input is unanswered, `null`, or another missing computed value is missing (`null`), not an error. Conditions over a missing value are false and wait on their inputs; rules over one fail with their own message. A computed value that errors with every input present is reported as a `defs.<key>` issue and reads as missing, so other fields, conditions, rules, and the fill state still evaluate and a session keeps asking for answers; the issue blocks completion. `@paradoc/expr` reports this case with the `missing-input` code and the `missing` paths, and exports `missingReferences`.
- The purchase order, proposal, and Arabic letter blocks derive their subtotal as `sum(fields.lineItems.amount)` (`sum(fields.items.amount)` in the letter), and their tax and total, like the invoice's, no longer guard against missing inputs. The hand-entered `subtotalAmount` field is gone, and `computeLineAmounts` returns only the rows.
- `@paradoc/render`: an enum or multiselect bound to a PDF text box, or drawn by a PDF overlay, writes the option value (the code the form expects, such as `C`, `5`, or `A`), not its label. The W-9 LLC classification, exempt payee code, and FATCA code boxes fill again; since field appearances were honored, their labels overflowed the boxes. Text, Markdown, HTML, and DOCX layers still print labels. `formatFieldData` takes `choices: 'value'` for the same behavior.
- `@paradoc/expr`: the checker keeps the numeric-index rule for arrays, so `list["key"]` reports a type mismatch instead of an unknown reference, matching evaluation. Bracket keys still read object members.
- `@paradoc/essentials`: the ACH debit and credit authorization PDFs put the variable amount source on its own full-width row, a wrapping box that fits any answer up to the field's new 100-character limit. Ordinary answers such as "as shown on monthly invoice" overflowed the old box and failed to fill. The signature placements now match the drawn signature lines.
- The `paradoc` skill's PDF bindings and layers references state the binding direction correctly: keys are template or PDF field names, values are Paradoc data paths.
- `@paradoc/render`: PDF text strings are read and written as the PDF specification defines them. Field names, text and dropdown values, and dropdown options decode as UTF-16BE after a FE FF byte order mark, UTF-8 after an EF BB BF one, and PDFDocEncoding otherwise; filling stores a value in PDFDocEncoding when it can and in UTF-16BE otherwise. `inspectAcroFormFields` and `form.extract` no longer misread values such as `文` or `•`, `—`, and `™`, and other strings (such as `/DA` and names) keep their exact bytes. Content-stream text and merged documents no longer change bytes 0x80 to 0x9F.
- CLI: `paradoc new <kind> --dir <path>` writes into an absolute `--dir` as given instead of nesting it under the working directory.
- The PDF reader stops with an error at a dictionary or array cut off by the end of the file. It used to keep reading past the end for seconds before giving up, so a truncated PDF stalled every PDF operation.
- The registry generator dropped an import alias, emitting `import { local }` for `import { exported as local }` so the installed file asked its module for a name that module does not export. It now keeps the alias and checks the exported name, not the local one, against the substrate's public entry. No component imported one; the packet block does.
- `paradoc check` binds a `.tsx`/`.jsx` composition through `tsx`'s programmatic loader, registered on demand and resolved against the composition's own nearest `tsconfig.json` (never the caller's cwd), so the published `paradoc` binary checks a real composition with no loader flags and no TypeScript-aware wrapper needed.
- A document that is still being filled can be rendered, if the caller says that is what it is. `FormatOptions.partial`, `<Document format={{ partial: true }} />` and `renderPdf(element, { partial: true })` turn it on for one formatter, one document or a whole tree; `checkComposition` turns it on for itself, because a check runs against whatever sample data there is and often against none. It is off everywhere else, so every ordinary render and both of the seal's render passes still fail on a value the data has not finished supplying: a finished document with a hole in it is a bug, and an em dash would hide it. With it on, a composite the serializer rejects because a member of it is blank — `{ amount: null, currency: 'USD' }`, the state a money def is in while the field behind its amount is unanswered — prints blank. It does **not** swallow a value that is wrong: whether a rejection is about a blank is decided by serializing the same value with its blank members removed and seeing whether the complaint survives, so `{ amount: '12', currency: null }`, which is half-supplied and also wrong, throws `InvalidFieldValueError` in partial mode as well as outside it. A composition using `Totals` now checks its schema cleanly with no sample data at all, as documented.
- `paradoc add` takes one or more component names in a single call (`paradoc add field table signature`) instead of silently keeping only the first; each requested name gets its own reported result.
- The sample purchase order can be filled by a session. Two of its fields could not be: `buyerContact` was invisible, so nothing asked for it and the packet could not bind the buyer's signer, and each line item's `amount` was required, so answering the rows meant doing the arithmetic first. The contact is visible and required, because not printing a field is the composition's decision rather than the artifact's. The row amount and `subtotalAmount` are both `visible: false` and `required: false`, declared identically because they are the same kind of thing: derived, never answered, and recomputed from the rows by `purchaseOrderDocumentData`. None of it changes a rendered byte. `sealVendorPacket` also names the party it cannot find, with `MissingPurchaseOrderPartyError`, instead of reading `id` off `undefined` when a fill is not finished.
- `@paradoc/sessions`' README documented `execute` with the wrong argument order and named a `view.target` the view does not have. Both corrected, and the rejection branch is shown, because it is the branch a live document depends on.

### Added

- `validateLayers()`, `paradoc validate`, and the `validate_artifact` AI tool check that bound values can fill a form's PDF text fields, laying values out with the same code filling uses, in the font filling would choose. A text field is checked at its `maxLength` or `pattern` length. An error names the layer, the PDF field, the artifact path, and the limit when a typical value of that length (the repeated English pangram `TYPICAL_TEXT`) cannot fit at 6 points, when an enum or multiselect option value cannot fit, or when a value or split part has more characters than a comb field has boxes. A warning is given when only the widest value (all `W` in Helvetica) overflows, or when a bound text field has no length bound. `validateLayers()` returns warnings in `result.warnings` and `validate_artifact` in `warnings`; neither fails validation. `paradoc validate` now prints layer issue messages in its human output. `@paradoc/render/pdf` exports the check as `checkPdfBindingFit()`.
- One condition language in templates. Text, Markdown, HTML, and DOCX templates keep their block markers (`{{#if}}`, `{{#unless}}`, `{{else}}`, `{{#each}}`; `{{IF}}`, `{{ELSE}}`, `{{FOR row IN list}}`), and everything inside a marker is an artifact expression evaluated by `@paradoc/expr`, with the same types, functions, decimal precision, and aggregates as field logic. Templates read the artifact's own expression context: `fields`, computed values by name, `parties.<role>`, and, in a checklist, `items.<id>`. A condition must be boolean and a loop source a list; `{{#each}}` binds `item` and `parent`, a DOCX `FOR` binds its named row, and `index(row)`, `first(row)`, and `last(row)` give a row's position inside a loop. Placeholders print a path formatted for its type and a computed value by its result type, with HTML escaping unchanged. Signing directives take expression arguments: `{{signature(parties.client, "client-sign")}}`, or `{{signature("client-sign")}}` inside a party loop.
- `validate()` checks the template expressions of inline layers; `validateLayers(artifact, { resolver })` also reads file-backed text and DOCX layers. Both report the layer, the line and column (or DOCX paragraph), and the expression. `paradoc validate` and the `validate_artifact` AI tool run both. `checkTextTemplate()` and `checkDocxTemplate()` check a template against a type environment, and a failed render throws `TemplateError` with the layer, position, and expression.
- Field logic reads typed party values through `parties.<role>`; a role that allows several parties is a list, so aggregates and row references apply (`count(parties.tenant) > 1`). An expression reads a key that is not an identifier with brackets, as in `items["signed-contract"]`.
- Text and DOCX renderers take `expressions: { functions, signatures }` for host-configured functions; a template cannot call a function without a signature.
- `@paradoc/render`: PDF filling and overlay text draw with embedded fonts. Each value uses the first font that can draw all of it: a font supplied at render time (`renderPdf({ font })`, `pdfRenderer({ font })`, `renderLayer({ pdfFont })`), then the font the PDF layer declares, then the form's own embedded TrueType font for the field, then Helvetica for Latin-1 text. Every font used is embedded, so names in Latin Extended, Greek, Cyrillic, and CJK scripts fill and display the same in any viewer. A character no font can draw fails with `PdfFieldFillError` (`missing-glyph`, naming the character); Arabic, Hebrew, Devanagari, Thai, and other scripts that need shaping fail with `unsupported-script`, pointing to the React composition path. A font that cannot be read, is not a TrueType-outline font, or forbids embedding fails with `PdfFontError` naming its source. A text overlay with a `width` now fails with `overflow` when its text cannot fit at 6 points, and field sizing and comb layout use the chosen font's metrics. Filled forms no longer ask viewers to regenerate field appearances (`NeedAppearances`), so every viewer shows the drawn values.
- Schemas: a PDF file layer can declare `font: { path, checksum? }`, a TrueType font read through the same resolver as the layer's PDF. The layer builder gains `.font()`. `paradoc registry compile` records the font's checksum, `paradoc add --layers` downloads and verifies it beside the layer, and the font counts as one of the artifact's file dependencies.

- `@paradoc/render`: filling an AcroForm PDF follows each field's own appearance settings. A value is drawn at the field's declared font size, or sized automatically when the size is 0, with the field's alignment and color; comb fields put one character in each box; multiline fields wrap and keep line breaks; a list box shows every selected value and a combo box shows the option's display text. A value that does not fit shrinks down to `MIN_FONT_SIZE` (6 points). Past that, or with more characters than a comb field has boxes, filling fails with `PdfFieldFillError`, naming the field, the reason (`overflow` or `comb-length`), and the limit. The bundled W-9 and 1099 forms now fill with digits in their comb boxes and right-aligned amounts.
- Dated schema versions. Every artifact file names the schema version it follows in `$schema`, with a dated address such as `https://schema.paradoc.dev/2026-09-22.json`. A new version is created only for a breaking change and ships with a migration step from the version before it. `@paradoc/schemas` exports `SCHEMA_VERSIONS`, `SCHEMA_VERSION`, `schemaVersionUrl`, and `readSchemaAddress`, which reads a dated bundle or individual schema address as its version and tells an undated, unpublished, or foreign address apart.
- `paradoc migrate <file-or-directory>` rewrites artifact files to the current schema version in place. It applies each migration step in order, keeps JSON as JSON with its indentation and YAML as YAML with its comments, and reports each file as migrated, current, or failed. `--dry-run` prints the diff and writes nothing; `--from <version>` names the version of a file with no `$schema` or the undated `schema.json`. A value a step cannot convert is named and that file is left unchanged, as is a result that does not validate; a file that does not parse is reported and a directory run continues. `@paradoc/core` exports the same as `migrateArtifact` and `migrateArtifactSource`, with `MIGRATION_STEPS` and `SchemaMigrationError`.
- Extraction of filled PDF forms. `form.extract(pdf, { layer? })` reads a filled PDF's AcroForm fields back through a PDF layer's bindings and returns `{ layer, data, report }`: `data` is a `{ fields, parties }` payload with only the values read back exactly (direct, nested, enum checkbox, radio, dropdown, and split bindings), and `report` has one entry per binding target (`recovered`, `empty`, `not_recoverable`, or `unparseable`, with the raw PDF values) plus the filled PDF fields no binding covers. A combined binding is reported as not recoverable, never split. Extraction does not validate: pass `data` to `fill`. Failures throw `PdfExtractionError` with a `code`, and a flattened or scanned PDF (`no_form_fields`) points to the hosted extraction service. `@paradoc/render/pdf` exports the underlying `extractPdfData` and `selectPdfExtractionLayer`.
- CLI: `paradoc data extract <form> <pdf-or-directory> [--layer] [--out]` writes the same result as JSON, for one PDF or every PDF in a directory.
- AI tools: a tenth tool, `extract`, takes a source plus the PDF as base64 (`pdf`) or a URL (`pdf_url`) under the layer file size limit, and returns the SDK result. The AI SDK, TanStack AI, and Mastra adapters expose it (`extract()`, `extractDefinition()`, `createExtractTool()`, and the `/extract` subpaths).
- `@paradoc/expr`: list aggregates. `sum`, `count`, `min`, `max`, `avg`, `any`, and `all` take a path into a list field and an optional boolean filter over the same rows: `sum(fields.items.amount)` totals every row, `sum(fields.items.amount, fields.items.taxable)` only the taxable ones. A path through nested lists collects every level, and a filter reads the row at its own depth. Rows hidden by their list, a field above it, or the list's `item` condition never count; `null` values are skipped, and an empty or all-hidden list gives `0` for `sum` and `count`, `null` for `min`, `max`, and `avg`, `false` for `any`, and `true` for `all`. Money keeps its currency and exact decimals; a sum across currencies fails with the `currency-mismatch` code, naming the currencies. The checker types each aggregate and reports, as `invalid-aggregate` or `type-mismatch`, an aggregate over an incompatible type, a non-boolean filter, a path that is not a list, a filter on a different list, and a list path read outside an aggregate. `createContext` takes `rowVisible` for hidden rows; `@paradoc/core` supplies it from the artifact, orders computed values after the conditions that hide their rows, and makes a fill-state condition over a list's rows depend on the list. There are no lambdas, `map`, `filter`, or `reduce`.
- The invoice block derives its subtotal as `sum(fields.lineItems.amount)` and taxes `sum(fields.lineItems.amount, fields.lineItems.taxable)`, the rows marked with the new `taxable` item field. The hand-entered `subtotalAmount` field is gone.
- `@paradoc/react`: the Chromium adapter draws page furniture. The header and the footer ride Chromium's own print templates, which repeat on every page and fill the page-number counters, and each template carries the page's stylesheet, its faces, and its root font size, so a band prints at the size and inset the preview draws it. The stamp is a whole-sheet layer behind the content, repeated on every printed page. A band taller than the margin fails with `PageFurnitureOverflowError` and a band image without bytes fails by name, as on the default engine; a page counter in the stamp is refused with `UnsupportedFurnitureContentError` naming the adapter and the slot, because Chromium fills no counter there. The parity suite measures a furnished proposal on both engines, page count, first unit, and the furniture's words and ink per page, and proves a foot that differs fails its page.
- Registry: `qr-code`, an inline SVG QR code that links a document to a URL, with a configurable size, colours, and accessible label. It reads nothing from the artifact and carries no pagination unit.
- Registry: `qr-code` fails by name with `EmptyQRCodeUrlError` when asked to encode an empty `url`, rather than drawing a code with nothing in it. Its PDF path is proven on the default engine and on the Chromium adapter: a rendered page rasterizes and decodes back to the URL it was given. Reaching the default engine at all needed one more fix: `preparePdfTree` now recognizes inline SVG markup, not just a `data:` URI, as an image that already carries its own bytes, so a composition holding a `QRCode` renders and passes `checkComposition`/`checkElement` with no caller-supplied image bytes.
- `@paradoc/react`: page furniture. `Pages`, `Paper`, and `renderPdf` take one `furniture` object of a `header`, a `footer`, and a `stamp`, each composed content: the preview draws the bands on every sheet and the default engine repeats them on every page through its own per-page mechanism, from the one declaration. A band is drawn inside the margin the document already declares, so the content budget, the page plan, and the page count are what they are without it; a band taller than that margin fails with `PageFurnitureOverflowError` naming the slot, the height it needed, and the margin it had, before any bytes are written. The stamp is drawn across the whole page behind the content. A new `page-number` registry item prints the page and the count, marking its two slots with `data-page-counter` so the adapter, not the component, names the engine's counter hooks; `usePageNumber()` answers for it in the preview. Classes and images in a band are checked against the verified vocabulary exactly as the document tree's are.
- Registry: `image`, a component that places a picture at a declared size, from its own bytes or from a source. Bytes are sniffed for their encoding and embedded as a `data:` URI, so neither output fetches anything; bytes no renderer decodes fail with `UndecodableImageError` naming the image, and an image with neither bytes nor a source fails with `MissingImageSourceError`. A `src` is passed through as the key the PDF path supplies bytes under, and `paradoc check` still reports every source with no bytes behind it. The picture is its own pagination unit. `@paradoc/react` exports the one resolution both sides share as `imageSource`, which caches an encoding against the array it came from so a tree rendered once per page does not re-encode its pictures; the proposal and invoice blocks' marks now go through the component rather than a hand-built keep. The size is written as attributes and inline, because the engine reads the first and a browser reads the second.
- Registry: `field` prints an attachment: `as="image"` draws the attachment at an annex path (`annexes.<slot>`) at the declared `width` and `height`, and prints its file name when its MIME type is not a picture, with the mismatch reported by `paradoc check` as `image:<path>`. An attachment is not a field value, so `DocumentData` gains `annexes` and `@paradoc/react` gains `useAnnex`, `resolveAnnex`, `readAnnex` and `UnknownAnnexError`, addressing slots with the same `annexes.<slot>` grammar the shared formatter already uses. A slot the artifact does not declare fails by name the way an unknown field path does, and `as="image"` with no `width` or `height` fails with `MissingImageSizeError` whatever the slot holds, so a composition cannot pass a check against a sample with nothing attached and then throw on the day a photograph arrives. `useAnnexPicture` is the binding that decides what a picture is and reports the mismatch, so a copied component cannot lose the check result.
- Registry: `field` prints long prose as paragraphs. `<Field paragraphs />` splits the value at its blank lines and gives each paragraph its own pagination unit, `field:<path>:<index>`, so prose longer than a page breaks between paragraphs in the preview and at the same paragraph in the PDF instead of overflowing the page as one oversize keep. The label stays with the first paragraph, and the wrapper withdraws from a page holding none of them the way a list's level does. A single paragraph taller than a page is still oversize: a pagination unit is never split inside itself. A newline inside a value remains a line break in both outputs, with or without the prop, which the composition skill now states.
- Registry: `<Field rule />` draws a fill line — `FIELD_RULE`, an underscore run like `Signature`'s — where the artifact has no value, instead of the document's blank placeholder, for a document printed before it is filled. `useField` reports that condition as `blank` on the binding: the placeholder is the document's own choice and a component cannot know the spelling it settled on, so the binding makes the comparison. It is not the same question as whether the value is nullish — a composite the serializer rejects because one member of it is unanswered prints blank too.
- Registry: `text`, static prose in a named role — `heading`, `body`, `caption`, or `small` — whose size and leading come from the document's `typography` token rather than a class written at each call site. Every `Text` is a `KeepTogether` with an id the composition chooses, so a paragraph is never split and the plan can name it as a break; an explicit `className` still replaces the role's classes outright.
- Registry: `list`, ordered or unordered items whose markers are text — `1.`, `a.`, `i.`, `•` — because the default PDF engine draws no list markers of its own and `list-*` is outside the verified class vocabulary, so the preview and the PDF draw the same characters. Every item is its own pagination unit keyed `<id>:<index>`, a nested level extends its parent's key and carries its parent's marker as a prefix (`2.b.`), and a level withdraws from a page holding none of its items the way a table does. Markers, item text and the gap between items all follow the `typography` token.
- `@paradoc/format`: a selection family, so boolean, enum, multiselect, and rating values are presented by the shared formatter rather than by each renderer. `formatBoolean`, `formatEnum`, `formatMultiselect` and `formatRating` (with their `safeFormat*` pairs, `formatValue('rating', ...)`, and standalone exports) take the options the field declares: the option list and an `unknownOption` policy for a value no option carries, `listType` and `listStyle` for the join, `trueLabel`/`falseLabel` for the boolean words, and `max`/`display` for the rating. Each is an override point and a `compose`/`withOverrides` layer like every other family, and each locale carries its own words: the five initial locales gain `rating.scale` beside `boolean.true`/`boolean.false`. A rating prints with its scale ("4 of 5", "4 von 5", "٤ من ٥"), and a multiselect joins its labels with the locale's own conjunction and separator, in the locale's direction, so an Arabic document reads right to left.
- `@paradoc/react`: an explicit page break. A `PageBreak` component installs from the registry as a `KeepTogether` that carries no content and a `data-break-before="page"` attribute; the measuring pass reads it onto `MeasuredKeep.breakBefore`, and `planPages` opens a fresh page for it the same way it already opens one for a keep that overflows, so an orphaned table header still carries forward ahead of it and the derived plan carries the break to both PDF engines with no change to either. A `table` prop lets a break placed between two of a hand-built table's rows repeat that table's header on the page it opens, the same as a row would.
- Registry: `party`, a component that prints one party of a declared role as a whole thing — name, organization, address, and contact each on their own line, as a block, or joined into one run inline — through the same shared formatter a `Field` reads through. `index` selects which party for a role a document may fill more than once. The artifact's own person/organization schema carries only name-shaped fields, so a filled party record that also carries its own `organization`, `address`, or `phone` member (the new `PartyWithContact` shape in `@paradoc/react`) has each one printed; a member the record does not carry is left off rather than printed blank. An undeclared role or an index past the filled parties fails by name, the latter with the new `PartyIndexOutOfRangeError`, the way an unknown `Field` path does.
- `@paradoc/react`: `underline`, `line-through`, `overline` and `no-underline` are admitted to the verified vocabulary. The original exclusion probed the class on a flex container the text sat inside, and takumi does not propagate `text-decoration` through one; probed directly on the text, takumi renders it. Vertical alignment (`align-super`, `align-sub`) and border styles (`border-dashed`, `border-dotted`) were re-probed the same way, against takumi-pdf and the Chromium adapter, and stay excluded — takumi still renders them byte-identical, Chromium does not. `safe-classes.md` reflects the new admission and names a substitute for what is still excluded.
- `@paradoc/react`: a DRAFT watermark. `rotate-*` (Tailwind's named steps, either way) is admitted to the verified vocabulary, probed as a stamp on both engines, so a `stamp` of `-rotate-45` text rises across every page of the preview and of the PDF on takumi and on the Chromium adapter. A stamp taller than the sheet now fails with `PageFurnitureOverflowError` naming the `stamp` slot and the sheet's height, and a stamp with a word wider than the sheet fails with the new `PageStampTooWideError`, where either was cut off at the paper's edge; the overflow error's `slot` widens to every furniture slot and its constructor takes the slot and a `FurnitureFit`. On takumi, a stamp with no header, or beside a header that is a bare `span`, was drawn in the top corner of the page with its rotation dropped; it is now centred and turned as in the preview. The `pages` reference page and the skill document the watermark.
- Registry: `table` gains three opt-in props, none changing today's default markup or page counts. `continuedLabel` shows on the repeated header once the plan marks it a copy, and only there: the header's own place in the flow holds a one-line placeholder at the label's metrics, and both PDF engines write the words on the copy alone. `footer` evaluates rows through `useTotals` and renders as one more keep, `` `${id}:footer` ``; the page planner gains a rule that a page opened for a table footer carries the table's last row with it. A column's `render(text, row)` replaces one cell's plain text with markup built from the already-formatted text and the row value, while the row still paginates as one unit.

### Changed

- **Breaking.** Loading enforces the schema version. An artifact file read from JSON or YAML must carry `$schema` naming the current version: `load()`/`safeLoad()`, every CLI command that reads an artifact file, `paradoc add`, the AI tools' URL and registry sources and `get_artifact`, and `paradoc check`/`paradoc dev` discovery. A missing, outdated, or unknown `$schema` fails with `SchemaVersionError` (`missing-version`, `outdated-version`, `unknown-version`), naming what it found, the current version, and `paradoc migrate`; loading never migrates. `loadFromObject()` and an inline AI-tool artifact accept an object without `$schema`, as an SDK-built artifact, but one they declare must be current. `assertCurrentSchemaVersion` applies the rule for any other surface.
- **Breaking.** `paradoc add` keeps the registry artifact's dated `$schema` in the installed file instead of stripping it, and refuses an artifact the registry serves for another version.
- `paradoc migrate --from` now names the version of any file whose `$schema` names no published version, not only a file with none.
- Every artifact in the workspace carries the current dated `$schema`: the bundled essentials, the `artifacts/` forms, the component examples and their registry output, and the CLI, AI tools, and platform fixtures. The staging HIPAA authorization used `indexOf`, which the expression language no longer has, and now uses `contains` as its design source does.
- **Breaking.** Schema version `2026-09-22` is current. It carries the breaking changes made since `2026-08-10`: signature placement `'auto'` is `'flow'`, an inline layer cannot hold a React composition, and a duration needs a date or time component. Its migration step renames `'auto'` to `'flow'` and names an inline React layer or an empty duration it cannot convert. The `2026-08-10` files are restored to what that release published, and every earlier dated version stays at its address.
- **Breaking.** Serialized artifacts carry the current dated `$schema` instead of the undated `schema.json`: `toJSON()` writes it first, and `toYAML()` now writes it as a key as well as in the editor comment. An artifact read with another address serializes with the current one, and `paradoc new` writes it too. `PARADOC_SCHEMA_URL` is the current dated address.
- `@paradoc/expr`: `min` and `max` over plain arguments skip `null` arguments, and return `null` when every argument is `null`, instead of failing with a type error.
- Registry: the shipped blocks compose with the components that now exist rather than with raw markup. The invoice, engagement letter, and purchase order set their titles with a `Text` heading and no longer size any line by hand, so the typography token moves every line of an installed block. The invoice and the engagement letter name their parties with `Party`, and their artifacts drop the `issuer`/`customer` and `firm`/`client` organization fields that repeated the party records; addresses and contact people stay fields, because the party schema carries neither. The purchase order keeps its organization fields, since a session fills it and `Party` refuses a role nobody has answered yet. Each block exports its footer as `invoiceFurniture`, `engagementLetterFurniture`, or `purchaseOrderFurniture`, a `PageNumber` that the block previews, the vendor packet, and the sealed letter and packet all draw. Page counts and the pages each signature lands on are unchanged.
- **Breaking.** `@paradoc/format`: a multiselect joins with the locale's list conjunction rather than a fixed comma, so `["Plumbing", "Roofing"]` prints as "Plumbing and Roofing" in `en-US` and "Plumbing und Roofing" in `de-DE`. Boolean and enum text is unchanged.
- `@paradoc/render`'s field formatter is a thin adapter over `@paradoc/format`'s selection family, so the text, DOCX, PDF, and React outputs print the same choice and rating text for the same values and formatter. A rating reaching the text, DOCX, or PDF path previously printed its raw number while a computed rating went through the number formatter; both now go through the rating formatter, and both fall back to the formatted number when the field declares no scale. The fallback keeps the formatter's structured outcome on the value, readable with the new `formattedValueIssues`. A checkbox binding still reads the stored value, not the formatted label.
- `@paradoc/react`: a `Field` (or `useField`) naming a fieldset or a list now throws the exported `CompositeFieldPathError`, naming the path and pointing at the list and party bindings, instead of printing `[object Object]`. `paradoc check` reports it as an unresolved path rather than stopping the walk.
- **Breaking.** Typography is application-owned. The `fontFamily` token and the registered families are gone: a document inherits the typefaces its application's stylesheet sets, and the faces the browser resolved are carried into the PDF, so the preview and the file use the same fonts without the package naming any.
- **Breaking.** The builder namespace is `p`, not `para`: `import { p } from "@paradoc/sdk"` and `p.form()`, `p.field.text()`, `p.party()`, and the rest. The CLI is invoked as `paradoc`; the `para` bin is gone from `@paradoc/cli` and `paradoc-cli`.
- **Breaking.** The file resolver is bound to the artifact at construction, not passed per call. `p.form(schema, { resolver })` — and the same second argument on `form.from`, `form.safeFrom`, the builder's `build()`, their `document` and `checklist` equivalents, `load`, `loadFromObject`, `safeLoad`, `safeLoadFromObject`, `runtimeFormFromJSON`, `runtimeDocumentFromJSON` and `runtimeChecklistFromJSON` — hands the artifact the resolver once, and every instance derived from it carries it. `RenderOptions`, `RuntimeFormRenderOptions`, `RuntimeChecklistRenderOptions`, `SealOptions` and the document's render options no longer take a `resolver`, and there is no fallback: a form that was constructed without one fails. This is what a runtime form has always needed. Core rebuilds the form from its config on every mutator, so a resolver that arrived with a `render` call was gone by the next `addSigner` or `setTargetLayer`, and `seal` and `prepareSeal` never saw it at all; `w9.fill(d).render({ layer: 'pdf' })` worked and `w9.fill(d).addSigner(...).render({ layer: 'pdf' })` did not. A file-backed layer with no bound resolver now throws the named `UnboundResolverError`, whose readonly `site` is `artifact` or `layers` and whose message names the remedy that site actually has. The site is not an input: it is decided by the entry point the render reached. `renderLayer(layers, layerKey, { resolver })`, which reads a bare layers record rather than an artifact, still takes the resolver as an argument, and always reports the `layers` site.
- **Breaking.** A bundle takes no resolver. `bundle.render()`, `assembleBundle` and `sealBundle` drop the option, because a packet's parts are artifact instances that each carry the resolver they were built with. The `<'bundle'>` overloads of `load`, `loadFromObject`, `safeLoad` and `safeLoadFromObject` take no options at all, and the untyped path refuses a resolver with the named `BundleResolverError` rather than dropping it. `ArtifactResolver` and `ResolvedArtifact`, the two exported types that existed only to describe the bundle option, are removed.
- **Breaking.** `@paradoc/essentials` artifacts no longer expose a `resolver` property, and no longer wrap `fill`/`safeFill` to patch a resolver onto the draft. Each artifact binds its bundled resolver when it constructs the form, so `w9.fill(data).render({ renderer, layer })` still needs no resolver and `w9.fill(data).addSigner(...).seal({ adapter })` now works, which it did not before.
- `@paradoc/react`: the preview waits for the document's own faces rather than for `document.fonts.ready`. That promise is about the faces the page has already requested, so on a cold page it resolves before layout asks for a glyph and the page plan is measured against fallback metrics; `Pages` now calls `document.fonts.load` for the resolved family and awaits `ready` after that. The request carries a letter of every script the family declares rather than the default text, which is a single space: a fontsource family is one face per subset with its own `unicode-range`, so a space is answered by the Latin face alone and every other face — for the Arabic family, the only one that matters — would stay unloaded.
- `@paradoc/react`: the fonts gate no longer consults `document.fonts.check`, and asks every face the set holds for the family for itself. `check` answers whether a text can be rendered, and a family the set holds no face for at all answers yes, because the browser can always fall back: a stylesheet whose `@font-face` rules have not reached the set yet is indistinguishable from a family already loaded, so skipping the request on that answer could open the gate onto the fallback. A request for a face already loaded resolves without a fetch, so asking every time costs nothing. And because `load` resolves once the faces covering *its text* are usable, a face whose `unicode-range` the probe does not reach stayed unloaded even though the PDF embeds it; each of the family's own faces is now asked for itself, so both outputs are set in the same faces.
- `@paradoc/react`: `Field` isolates a `phone` or `identification` value in a right-to-left document. Both are runs of digits and punctuation that the bidirectional algorithm gives no direction of their own, so a right-to-left paragraph moves the leading `+` of an E.164 number to the visual end. The value is not changed and no serializer is touched: the span carries `direction: ltr; unicode-bidi: isolate`, as the `paradoc-ltr-isolate` class for the browser and inline for a renderer that reads no stylesheet. Left-to-right documents are untouched, so their bytes are unchanged.
- `RenderPdfOptions.lang` is removed. The language is a document token now, so a render that wants another one passes `tokens: { lang }` and layers it the way it layers any other token; two ways to say it would have been two things to keep in step. `renderPdf`'s `dir` never shipped as an option.
- `@paradoc/types`: `RendererLayer.content` is optional, because a layer that names its content rather than carrying it — a React composition — has none. `key` and `path` are added, so a renderer that binds a module knows which layer it is rendering. A `FileLayer`'s `path` is documented as relative to the artifact file that declares it, which is what artifacts have always written; it previously said "absolute path from repo root".
- `@paradoc/render`: `renderLayer` fails naming the MIME type when a layer of a type it renders carries no content. An unsupported type is still reported as unsupported.
- `@paradoc/react`: `Pages` decides a repagination from the measurement, not from the identity of its children. It measures again after every render, before paint, and replaces the plan only when the new plan differs, so a host that passes an inline object prop or sets state from `onPaginate` publishes one plan instead of looping, and the sheets that survive an edit keep their DOM nodes.
- The marker-based placement literal is `'flow'` (was `'auto'`): the field sits where the template content places it, mirroring flow/anchored/absolute positioning. Clean rename, no alias; artifacts published with `'auto'` under 0.5.0 must update the literal.
- The bundled essentials forms and example artifacts declare `signatures` slot maps instead of legacy `signatureBlocks`. Legacy blocks remain readable during the deprecation window.
- **Breaking.** `@paradoc/ai-tools`: one contract of nine operations, `get_registry`, `get_artifact`, `inspect_artifact`, `validate_artifact`, `validate_input`, `fill`, `get_fill_state`, `update_fill`, and `render`, exported as `toolDefinitions` and `operationNames` with Zod input and output schemas and an `execute*` function per operation. `inspect_artifact`, `get_fill_state`, and `update_fill` are new. `ValidateOutput` is now `ValidateArtifactOutput` and `ValidateInputValueOutput` is `ValidateInputOutput`.
- **Breaking.** `@paradoc/core`: filling is progressive. `fill()` and `safeFill()` accept partial data and leave omitted values open, and `update()` adds more. `partialFill`, `safePartialFill`, `PartialFillOptions`, `FillValidationMode`, and the fill `validate`/`rules` options are removed.
- **Breaking.** `@paradoc/resolvers`: two entry points, `@paradoc/resolvers/fs` (`createFsResolver`) and `@paradoc/resolvers/memory` (`createMemoryResolver`); the package root no longer exports anything. `@paradoc/core` no longer exports `createMemoryResolver`, `MemoryResolverOptions`, or `Resolver` (the `Resolver` type is in `@paradoc/types`).

### Removed

- **Breaking.** `@paradoc/sessions`: the spine adapter is removed. `createSpineStateAdapter`, `spineEventToAgentEvent`, `agentEventToSpineAppend`, `SpineConflictError`, `SessionSpinePort`, `SpineEvent`, `SpineAppend`, and `SpineAppendResult` had no users; `@paradoc/sdk` no longer re-exports them. Persist `session.events` yourself and replay them with `deriveView`; the sessions docs now state that a store must keep events append-only, in order, and without duplicates.
- **Breaking.** `@paradoc/schemas`: `GlobalConfigSchema` drops `enableTelemetry`, which nothing read; use `telemetry.enabled`. The schema adds `telemetry: { enabled }`, `security: { allowedContentTypes }`, and `anonymousId` (a UUID), and `telemetry` and `security` reject unknown keys.
- The template helper dialect and the DOCX comparison evaluator. `eq`, `ne`, `gt`, `gte`, `lt`, `lte`, `not`, `and`, `or`, `contains`, `default`, helper call syntax, `{{#with}}`, `this`, `../`, `@root`, `@index`, `@first`, `@last`, `@key`, looping over objects, DOCX `===`/`!==` and `$row` names are no longer accepted; validation names each replacement (`==`, `and`, `in`, `coalesce`, full paths, `item`, `parent`, `index(item)`). Registering template helpers (`registerSignatureHelpers`, `createSignatureHelper` and its siblings, `createDocxSignatureHelpers`) is removed; `createTextSignatureDirectives` and `createDocxSignatureDirectives` replace the helper sets. Every template in the repository, including the essentials forms, examples, fixtures, and documentation, uses the new syntax.
- `@paradoc/serialization` is retired; use `@paradoc/format`. `@paradoc/sdk` no longer re-exports it. `@paradoc/types` drops `SerializerRegistry`, `SerializerConfig`, `SerializerFallbacks`, `RegionFormat`, `Stringifier`, and `BaseRendererOptions`, and the render context's `locale` and `serializers` give way to `formatter`.

## [0.5.0] - 2026-08-10

### Added

- Unified `signatures` slot map on layers. Each slot binds a party to a placement: `'auto'` (an invisible marker injected at render time and located after conversion), a text `anchor` (unique in the document, or selected with `occurrence`), or absolute coordinates. One placement engine resolves all three, and misconfiguration fails before rendering with a `SealConfigError` naming every problem. Legacy `signatureBlocks`/`anchorBlocks` still parse and seal unchanged.
- A built-in placement locator in `@paradoc/render`: a dependency-light PDF text scanner (`locate`, `extractFieldsFromPdf`, `pageTextRuns`, marker encoding) that resolves signature positions in converted PDFs without a PDF rendering engine. Exported from `@paradoc/render/pdf` and re-exported by `@paradoc/sdk`.
- `prepareSeal()` on draft forms: resolves the signature map and returns the exact pre-flatten PDF it describes, with per-field provenance (`declared` | `anchor` | `marker`) and warnings, without changing the form's phase.
- `SealOptions.locate` to substitute a custom placement locator.
- The schema version `2026-08-10` adds the `SignatureSlot` layer schema; the published `2026-08-06` schemas remain available unchanged.

### Changed

- Anchor-based sealing works with pure byte converters, including `hostedSealAdapter`, with zero configuration: core locates anchor text itself in the converted PDF. Adapters that resolve placements themselves still take precedence.
- The sealing guide is rewritten around signature slots, placement strategies, and pure converters.

### Fixed

- `PdfModel` resolves indirect `/Length` stream references, so PDFs written by LibreOffice no longer lose trailing stream bytes.

### Removed

- The unused `SealingRequest.options` block (`renderer`, `format`). It was never read by any implementation.

## [0.4.0] - 2026-08-06

### Changed
- Form rendering and sealing use the built-in MIME-selected renderer by default while preserving custom renderer overrides. The CLI and integrations use the same unified renderer.
- The current schema version is `2026-08-06`; the published `2026-01-01` schemas remain available unchanged.

### Added
- `@paradoc/render`, a dependency-light renderer for text, Markdown, HTML, PDF, and DOCX layers, including template control flow, PDF AcroForm filling, overlays, inspection, page selection, and flattening.
- Recursive List fields across builders, types, schemas, validation, serialization, and rendering.
- A sealing boundary with local PDF flattening and optional adapters for non-PDF conversion.

### Removed
- The legacy `@paradoc/renderers`, `@paradoc/renderer-text`, `@paradoc/renderer-pdf`, and `@paradoc/renderer-docx` packages.
- Heavy PDF, DOCX templating, and Handlebars dependencies from the rendering and e-signing paths.

## [0.3.0] - 2026-06-19

### Added
- `@paradoc/expr`: a purpose-built, typed expression language for artifacts — a parser, an evaluator, and an artifact-aware type checker sharing one function registry. Exact-decimal arithmetic (no floating-point drift), temporal types (date, datetime, time, duration), `in` / `not in`, and null-safe access.
- `@paradoc/sessions` is now published: the deterministic, event-sourced form-completion session engine.
- Dependency-aware fill state: a single `status` ordinal (`hidden`, `optional`, `required`), transitive `blockedBy`, and DAG-ordered next-field.
- The expression engine is reachable through `@paradoc/sdk` as the `expr` namespace (`expr.check`, `expr.parse`, `expr.Decimal`).
- Documentation for `@paradoc/sessions` and `@paradoc/expr`, and the fieldset visibility cascade.

### Changed
- Artifact logic now runs on `@paradoc/expr`. A hidden fieldset hides its entire subtree, and a child's required follows its effective visibility.

### Removed
- The `expr-eval-fork` dependency.
