# Changelog

All notable changes to Paradoc. Packages are versioned in lockstep.

## [Unreleased]

### Added

- `@paradoc/react`: compose a document from React components bound to a form artifact. One tree drives a paginated preview in the browser and a PDF from Node, with the preview's page breaks honored when its plan is passed as hints. The root entry carries the components, the document context and the page plan; `@paradoc/react/pdf` carries `renderPdf`, the adapter seam, the default WebAssembly engine and the layer renderer core renders and seals through; `@paradoc/react/chromium` carries the experimental Chromium adapter, whose `puppeteer` and `tailwindcss` peers are optional and whose absence fails with one error naming both. `@paradoc/react/examples` and `@paradoc/react/examples/pdf` carry a worked sample document as sample material rather than API.
- `@paradoc/react`: tenant branding tokens on `Bundle` and `Document`. `fontFamily`, `accentColor`, `pageSize` (`letter` or `a4`) with `marginPx`, and `logo` (bytes or a source string), declared at the document root and layered over by `renderPdf`'s own `tokens` for a per-render override. The resolved set drives both outputs: the paper the preview's sheet is drawn on and the page the engine writes, the faces the browser loads and the engine embeds, the accent on section headings and the emphasised total, and the mark a composition places through `useDocumentTokens()`. Two families are registered, `Inter Variable` and `Source Serif 4 Variable`; naming any other fails with `UnregisteredFontFamilyError` rather than falling back, because a family the engine cannot embed reaches paper as null glyphs. The furniture and `renderPdf` read the tokens off the element with one pure, synchronous `documentTokensOf`, so a static render and the first browser commit are already on the right paper. Paper and typeface are root-only: a nested `Document` that sets them fails with `NestedPaperTokenError`, and a root that resolves a root-only token differently from whatever is drawing it fails with `RootTokenMismatchError` naming the token, on the PDF path as well as in the preview. Every value is checked before a renderer sees it, with `InvalidDocumentTokenError` naming the token. The default token set renders the reference documents byte for byte as before.
- `@paradoc/serialization` registries gain `date`, `datetime`, `time`, `number`, and `percentage` stringifiers, locale-aware through `Intl` with the same fixed options per registry as the existing composite serializers. `@paradoc/render`'s text, DOCX, and PDF field serializer does not yet dispatch these five types, so a date field still emits raw ISO text in those layers; that follow-up is tracked separately.
- React layers by MIME type. A file layer of MIME type `text/tsx` or `text/jsx` names a composition module; an inline layer of either type is rejected at validation with a message naming the rule. MIME types compare without regard to case, so validation and render dispatch read `TEXT/TSX` the same way. `render({ layer, renderers })` selects a renderer from a MIME-keyed registry — on forms, documents and checklists — so `@paradoc/core` dispatches to a React composition without depending on React: `reactLayerRenderers()` from `@paradoc/react/pdf` builds the registry entries, and binds the layer's module from a `components` map keyed by path or layer key, or by importing the path's default export. Import binding executes the module the artifact names, so the path must be relative and resolve inside `baseDir`. A layer that cannot be bound fails naming the path and both options; a React layer with nothing registered fails naming the layer and the option. `reactLayersOf(artifact)` reports which layers an artifact declares that way. `@paradoc/react/examples` declares its composition layer.
- `para dev`: a live preview of every composition in a project, paginated on screen with its sample data beside the PDF the same tree renders to, with the preview's page breaks passed as hints. A composition whose class the engine cannot express, or whose path the artifact does not declare, shows the finding in place of the PDF; so does one with no artifact, or one whose document throws while it draws. A planned page break the tree no longer carries is named rather than dropped in silence. `--list` prints what the conventions found and exits, `--list --json` reports it as data. The preview uses the project's own toolchain: `vite`, `@vitejs/plugin-react`, `@tailwindcss/vite`, `tailwindcss`, `@paradoc/react`, `react` and `react-dom` are optional peers of `@paradoc/cli`. `@paradoc/react`, `react` and `react-dom` are resolved at the project and nowhere else, because the page loads them; a project missing any of the seven is told which, in the install commands of whichever package manager left a lockfile. Nothing is written to disk.
- `@paradoc/react/discovery`: the conventions that connect a composition to its artifact and its sample, in one place so `para dev` and `para check` cannot disagree. A composition is a `.tsx` or `.jsx` file under a `compositions/` directory; its artifact is the form whose `text/tsx` or `text/jsx` file layer resolves to it, or failing that an artifact file of the same name beside it; its sample data is a sibling `<name>.sample.{ts,tsx,js,mjs,jsx}` before a `sample` export on the composition itself. `para check` now follows the same two fallbacks, which it previously did not.
- The Zod rule and the JSON Schema keyword it emits land now; the dated schema sets under `@paradoc/schemas` are regenerated at release, so `schema.paradoc.dev` carries the rule from the next one.
- Seal markers from the composition itself. `SealOptions` takes the same `renderers` registry `render` takes, and the seal now runs a registered renderer wherever it can: for a React composition it is the renderer the seal uses, producing the PDF itself, so no `SealAdapter` is required and flow placement is no longer refused for it; for every other layer `renderer`, then the registry, then core's own, which is `render`'s own order. The one exception is a flow pass, which only core's marker-injecting text renderer can produce, so an override alongside flow placement is still a `SealConfigError` before anything renders. The flow markers travel to a composition's renderer as `ctx.signing`, typed as `SigningMarkerRequest` in `@paradoc/types`, keyed by slot id and naming the slot's party, index, field type and marker.
- `@paradoc/react`: `Signature` draws one slot. It takes a `type` (`signature` or `initials`, default `signature`) and finds its own marker by party, index and type, so a party signing and initialling is two blocks and two flow slots rather than two slots collapsed into one. A party may carry one flow slot per field type; two of a type on one party fails with `AmbiguousSigningMarkError` naming both. `INITIALS_RULE` joins `SIGNATURE_RULE` and `DATE_RULE`. The composition seals with the slots declared on its own layer and no auxiliary text layer, and a marker the PDF did not receive fails at the render with `MissingSigningMarkerError` naming the slot and glyph coverage.
- Core's own placement failure names the likely cause too: when a marker pass produced a PDF carrying no marker codepoint at all, the `LocateError` gains a sentence about glyph coverage and the codepoints involved, so a third-party renderer that does not check its own output still fails saying what happened.
- A shadcn registry of the document components, served at `https://docs.paradoc.dev/r/{name}.json` under the `@paradoc` namespace. Twelve component items — `bundle`, `document`, `field`, `keep-together`, `pages`, `paper`, `part`, `pdf-pages`, `section`, `signature`, `table`, `totals` — install their source into `components/paradoc/` with the stock CLI (`npx shadcn@latest add @paradoc/field`) or with `para add field`, which registers the namespace in the project's `components.json` first. Generated from the component sources by `pnpm registry:build` in `@paradoc/react`, never hand-written: the generator rewrites every import so the installed file compiles as emitted, and refuses to emit one that reaches for something the package does not export publicly or an npm package the item does not declare. Every `@paradoc/*` dependency is emitted at this package's own version, so an installed component and its substrate stay in lockstep.
- `@paradoc/react` exports the substrate an installed component stands on: `createDocumentContext` and `DocumentContextProvider`; `PageContextProvider`, `usePage`, `useKeepVisible`, `useSectionVisible` and `PageContextValue`; `useSigningMarks`, which `Document` calls on every render and which the browser entry previously did not carry; `markDocumentRoot`, `useDocumentRootTokens`, `useTokenOverride` and `ResolvedRoot`; and `drawnPaper`, `DrawnPaperProvider`, `useDrawnPaper` and `DrawnPaper`. A copied component reads the same contexts the package's own `Pages` provides rather than forking them.
- `para add <name>` installs a document component through `npx shadcn@4`, after registering the `@paradoc` namespace in the project's `components.json`. A name the registry ships is a component; a namespaced reference, a URL, or any other bare name is still an artifact. `--registry` points at a mirror and `--dry-run` prints the install command.
- Right-to-left documents. `dir` and `lang` join the document tokens as root-only values, so one declaration reaches the preview's sheet and the render alike and gets the machinery the typeface already had: the element walk, `NestedPaperTokenError`, `RootTokenMismatchError`, and a per-render override. The document root writes them onto its element as HTML carries them, and only when they are not the defaults, so a document that never asked about its script renders the bytes it always did. `Noto Sans Arabic Variable` is registered as a third family, pinned exactly in the catalog for the reason the other two are, and every registration now declares the ISO 15924 scripts it carries glyphs for: a family that cannot set the document's script fails with `UnsupportedScriptError` naming the script, the family, and the family that would work, rather than reaching paper as null glyphs. The tag is only a declaration, so the same error is raised from the document's own text as well: the root reads the artifact's labels and the data's values in one memoized pass as it resolves, and the PDF path's tree walk reads every text node after the components have run, which catches a composition that declares no language and is Arabic anyway — a whole document of null glyphs that nothing else would have reported. A `PdfAdapter` declares the writing directions it was measured to lay out, and `renderPdf` refuses a pairing it cannot make with `UnsupportedDirectionError` naming the adapter and the script. takumi declares left to right only — it shapes Arabic and reverses a flex main axis for `dir="rtl"`, but it has no `direction`, so every line would still start on the left; Chromium declares both and is measured on the Arabic document against the same four parity criteria with nothing loosened. `@paradoc/react/examples` ships that document: a short Arabic order-confirmation letter with a priced schedule that paginates onto two pages.
- `@paradoc/serialization`: an `ar` registry, reachable as `createSerializer({ regionFormat: "ar" })` and as `arSerializers`. Arabic month names, meridiem and currency names, with the numbering system pinned to Latin digits in the locale tag (`ar-u-nu-latn`) rather than left to the runtime's CLDR default, which has moved between ICU releases. Arabic-Indic digits are a second registry nothing has needed yet.
- `@paradoc/react/check`: `checkComposition` resolves a composition against its artifact in a check mode that records every unresolved `Field`/`Table` path and `Signature` party role instead of throwing on the first one, and reports what a render would refuse — those, classes outside the default adapter's verified vocabulary, and image sources with no embedded bytes, all in one pass — without producing PDF bytes. `para check <composition-or-artifact>` runs it from the CLI, installing `@paradoc/react` on first use the way `para render` installs `@paradoc/render`, exits non-zero on any offender, and prints each one with its file and path.
- `compose-documents`, an agent skill under `paradoc/skills/skills/` alongside the existing `paradoc` skill: the component vocabulary and props, the keep-together pagination rule, the verified Tailwind class subset and its failure modes, the branding token set, binding a composition to a form artifact's React layer, the seal's marker emission, and `para check`/`para add`. The docs site's components page gains a "For agents" section pointing at the machine-readable `/r/registry.json` index and `para check`, and `para check` itself now has a CLI reference page.
- Packets. `sealBundle(bundle, { contents, renderers, resolver, signers })` in `@paradoc/core` seals a bundle as one thing: each part reaches PDF on its own terms (a form with slots through its own `prepareSeal`, anything else through ordinary assembly), is flattened so its filled values are page content, and the parts are merged in bundle order into one document. It returns that document with `canonicalPdfHash` over it, which is **the hash a signing ceremony binds to** because it is the document the signer is shown; `packetHash`, the packet's record over the merged document plus every part beside it, which accounts for a part nobody could paint and is not what a signer signs; a `signers` registry; one `signatureMap` whose `page` is a packet page and whose `id` is `<part>/<slot>`; a `parts` list giving each part its page range and digest; and `warnings` naming every part carried rather than merged.
- Packet signers are the packet's, not the parts'. A part binds signer ids in its own namespace, so `sealBundle` scopes every one as `<part>/<signerId>` and treats two parts that both bind `signer-1` as two people. `BundleSealOptions.signers` maps part signers onto one packet signer when they are the same person, and naming a part signer nothing binds fails rather than silently leaving two. `signerIndex` on the map indexes the registry; `partSignerId` on each field keeps the id the part itself bound.
- A packet checks its parts before it seals them: an entry must be the artifact the bundle declares, by name and version or by the last segment of a registry slug, and a bytes entry must sniff as the type it declares. A rendered part whose renderer produced something other than a PDF is a `SealConfigError` naming the part; any other per-part failure is a `BundleSealError` whose `part` names it. An annex declared as a PDF whose bytes cannot be read is not a failure: it becomes an attachment with its digest in the packet record and a warning naming it.
- `assembleBundle` accepts content that arrives as bytes: `{ kind: 'bytes', content, mimeType, filename }`, which is what an annex is. It also names a part by what its renderer produced rather than by the layer's own type, so a React layer's part is `application/pdf` with a `.pdf` filename instead of `text/tsx` with a `.bin` one.
- `@paradoc/render`: `mergePdfs(sources)` concatenates PDFs into one document, writing a fresh file with every page in order at its own size, deterministically. A single source is returned unchanged. Every failure names its source: `PdfMergeError` carries the zero-based index for a document with no catalog, no pages, an encryption dictionary, or bytes the parser cannot read. A merge drops everything the old catalog held rather than the page, which the README lists in full: the interactive form, the structure tree (leaving `StructParents` on copied pages dangling), the name tree and destinations, optional content, `Lang`, `ViewerPreferences`, outlines and metadata.
- `@paradoc/react`: `Part` and `PdfPages` put a packet on screen as separate documents in one scroll. `Part` is the boundary between them, so each numbers its own pages and says which packet pages it occupies, or that it is attached rather than paginated, or that its pages are pending when the placement was computed for a packet other than the one on screen. `PdfPages` paints a PDF part page by page at its own paper size and takes `standardFontDataUrl` and `cMapUrl`, the assets pdf.js does not bundle and waits on. Every paint is bounded by `timeoutMs`, 20 seconds by default, and a paint that fails or runs out becomes a named `Attachment` card saying why, reported through `onPaint`. Painting uses `pdfjs-dist`, a new optional peer loaded on demand: a module that is not installed gives `MissingPdfPainterError` naming the package, and every other load failure is reported as itself.
- `@paradoc/react/examples` gains the vendor packet: a purchase order artifact with a React layer and its composition, a certificate of insurance standing in for an uploaded annex, the `vendorPacket` bundle declaring all three parts, `VendorPacketDocument` showing them in one scroll, and `sealVendorPacket` in `@paradoc/react/examples/pdf`. The W-9 is not a dependency of the package: the bundle names it by registry slug and the caller hands in the filled draft. The annex is checked in as `@paradoc/react/examples/certificate-of-insurance.pdf`, so a project installing the block has annex bytes without a Node render; `pnpm --filter @paradoc/react regenerate:annex` redraws it.
- Two registry blocks, `purchase-order` and `vendor-packet`. A block is a whole document rather than one component: `para add purchase-order` (or `npx shadcn@4 add @paradoc/purchase-order`) installs the purchase order artifact, its sample order and the composition that binds them; `vendor-packet` installs the packet's bundle artifact, its sample, the annex bytes and the composition that lays its three parts out, and brings `purchase-order` with it because the order is one of those parts. The composition lands in `components/paradoc/` beside the components; the artifact and its data land in `artifacts/paradoc/`, because they are not components. Both are generated from the same sources the package renders and seals in its own suites, so a block cannot drift from the document those suites measure. `vendor-packet` declares `@paradoc/essentials` without importing it: the packet's second part is the IRS W-9, which cannot be filled or sealed without that artifact and its resolver, so the sample carries the taxpayer's values rather than the form.
- The vendor packet's annex travels as bytes. A registry item is JSON, so it cannot ship a PDF; the registry generator reads the checked-in certificate through a binary path and emits `vendor-packet.annex.ts`, a module exporting the bytes as a `Uint8Array`, so a block installed into a browser project has an annex without a Node render. The same generation writes the module into `@paradoc/react`'s own `src/`, which is what `vendorPacketData` hands `VendorPacketDocument`, and the registry's freshness test regenerates both copies.
- `@paradoc/react/examples` gains `vendorPacketData`: one entry per packet part — the purchase order's data, the taxpayer's values for the W-9, and the annex bytes. The purchase order sample now runs to three pages, so its table continues across two breaks; a continued page's repeated header comes from the page plan, so it appears in the preview and in a hinted PDF.
- Filling a packet in a session. `@paradoc/sessions` exports `sessionPayload(projected)`, the projection from a session's event log to the artifact's own shape: answers unwrapped and un-flattened into nested fields, parties keyed by role rather than by `roleId#index` and given the array when a role is filled more than once. It is the same projection the engine already used internally to ask core for a fill state, so what core evaluates and what a caller renders can no longer be shaped differently, and it is valid at every point of a fill rather than only at the end. Binding it to a composition is one `useMemo` on the session: an accepted answer produces a new session and redraws the document, and a rejected one produces none, so the host holds the session it had and React re-renders nothing.
- `@paradoc/react/examples`: `purchaseOrderDocumentData(payload)` turns what a session has answered into the purchase order's document data, computing the two values that are arithmetic rather than answers — each row's `amount` and `subtotalAmount` — on every call, so the totals follow the rows as they land. `purchaseOrderAnswers` is the same sample with those two taken back out, which is what a filler actually supplies.
- The lab gains a third view, `?view=session`: two sessions fill the vendor packet's two fillable artifacts in the browser against the real engine, the purchase order composes live beside the fill log, one value is offered wrong before it is offered right, and the completed packet renders and seals from what the sessions collected. The dev server's packet route takes those answers as a POST body.

### Fixed

- The registry generator dropped an import alias, emitting `import { local }` for `import { exported as local }` so the installed file asked its module for a name that module does not export. It now keeps the alias and checks the exported name, not the local one, against the substrate's public entry. No component imported one; the packet block does.
- `para check` binds a `.tsx`/`.jsx` composition through `tsx`'s programmatic loader, registered on demand and resolved against the composition's own nearest `tsconfig.json` (never the caller's cwd), so the published `para` binary checks a real composition with no loader flags and no TypeScript-aware wrapper needed.
- A document that is still being filled can be rendered, if the caller says that is what it is. `FormatOptions.partial`, `<Document format={{ partial: true }} />` and `renderPdf(element, { partial: true })` turn it on for one formatter, one document or a whole tree; `checkComposition` turns it on for itself, because a check runs against whatever sample data there is and often against none. It is off everywhere else, so every ordinary render and both of the seal's render passes still fail on a value the data has not finished supplying: a finished document with a hole in it is a bug, and an em dash would hide it. With it on, a composite the serializer rejects because a member of it is blank — `{ amount: null, currency: 'USD' }`, the state a money def is in while the field behind its amount is unanswered — prints blank. It does **not** swallow a value that is wrong: whether a rejection is about a blank is decided by serializing the same value with its blank members removed and seeing whether the complaint survives, so `{ amount: '12', currency: null }`, which is half-supplied and also wrong, throws `InvalidFieldValueError` in partial mode as well as outside it. A composition using `Totals` now checks its schema cleanly with no sample data at all, as documented.
- `para add` takes one or more component names in a single call (`para add field table signature`) instead of silently keeping only the first; each requested name gets its own reported result.
- The sample purchase order can be filled by a session. Two of its fields could not be: `buyerContact` was invisible, so nothing asked for it and the packet could not bind the buyer's signer, and each line item's `amount` was required, so answering the rows meant doing the arithmetic first. The contact is visible and required, because not printing a field is the composition's decision rather than the artifact's. The row amount and `subtotalAmount` are both `visible: false` and `required: false`, declared identically because they are the same kind of thing: derived, never answered, and recomputed from the rows by `purchaseOrderDocumentData`. None of it changes a rendered byte. `sealVendorPacket` also names the party it cannot find, with `MissingPurchaseOrderPartyError`, instead of reading `id` off `undefined` when a fill is not finished.
- `@paradoc/sessions`' README documented `execute` with the wrong argument order and named a `view.target` the view does not have. Both corrected, and the rejection branch is shown, because it is the branch a live document depends on.

### Changed

- `@paradoc/react`: the preview waits for the document's own faces rather than for `document.fonts.ready`. That promise is about the faces the page has already requested, so on a cold page it resolves before layout asks for a glyph and the page plan is measured against fallback metrics; `Pages` now calls `document.fonts.load` for the resolved family and awaits `ready` after that. The request carries a letter of every script the family declares rather than the default text, which is a single space: a fontsource family is one face per subset with its own `unicode-range`, so a space is answered by the Latin face alone and every other face — for the Arabic family, the only one that matters — would stay unloaded.
- `@paradoc/react`: the fonts gate no longer consults `document.fonts.check`, and asks every face the set holds for the family for itself. `check` answers whether a text can be rendered, and a family the set holds no face for at all answers yes, because the browser can always fall back: a stylesheet whose `@font-face` rules have not reached the set yet is indistinguishable from a family already loaded, so skipping the request on that answer could open the gate onto the fallback. A request for a face already loaded resolves without a fetch, so asking every time costs nothing. And because `load` resolves once the faces covering *its text* are usable, a face whose `unicode-range` the probe does not reach stayed unloaded even though the PDF embeds it; each of the family's own faces is now asked for itself, so both outputs are set in the same faces.
- `@paradoc/react`: `Field` isolates a `phone` or `identification` value in a right-to-left document. Both are runs of digits and punctuation that the bidirectional algorithm gives no direction of their own, so a right-to-left paragraph moves the leading `+` of an E.164 number to the visual end. The value is not changed and no serializer is touched: the span carries `direction: ltr; unicode-bidi: isolate`, as the `paradoc-ltr-isolate` class for the browser and inline for a renderer that reads no stylesheet. Left-to-right documents are untouched, so their bytes are unchanged.
- `RenderPdfOptions.lang` is removed. The language is a document token now, so a render that wants another one passes `tokens: { lang }` and layers it the way it layers any other token; two ways to say it would have been two things to keep in step. `renderPdf`'s `dir` never shipped as an option.
- `@paradoc/types`: `SerializerConfig.regionFormat` is a named `RegionFormat` and admits `ar`.
- `@paradoc/serialization` exports `REGION_REGISTRIES`, the built-in registries by the name a caller asks for them by, exhaustive over `RegionFormat` by construction. `createSerializer` and `@paradoc/react`'s formatter both select from it, so neither carries a second list nor a fallback for a name that cannot exist.
- `@paradoc/types`: `RendererLayer.content` is optional, because a layer that names its content rather than carrying it — a React composition — has none. `key` and `path` are added, so a renderer that binds a module knows which layer it is rendering. A `FileLayer`'s `path` is documented as relative to the artifact file that declares it, which is what artifacts have always written; it previously said "absolute path from repo root".
- `@paradoc/render`: `renderLayer` fails naming the MIME type when a layer of a type it renders carries no content. An unsupported type is still reported as unsupported.
- `@paradoc/react`: `Pages` decides a repagination from the measurement, not from the identity of its children. It measures again after every render, before paint, and replaces the plan only when the new plan differs, so a host that passes an inline object prop or sets state from `onPaginate` publishes one plan instead of looping, and the sheets that survive an edit keep their DOM nodes.
- The marker-based placement literal is `'flow'` (was `'auto'`): the field sits where the template content places it, mirroring flow/anchored/absolute positioning. Clean rename, no alias; artifacts published with `'auto'` under 0.5.0 must update the literal.
- The bundled essentials forms and example artifacts declare `signatures` slot maps instead of legacy `signatureBlocks`. Legacy blocks remain readable during the deprecation window.

## [0.5.0] - 2026-08-10

### Added

- Unified `signatures` slot map on layers. Each slot binds a party to a placement: `'auto'` (an invisible marker injected at render time and located after conversion), a text `anchor` (unique in the document, or selected with `occurrence`), or absolute coordinates. One placement engine resolves all three, and misconfiguration fails before rendering with a `SealConfigError` naming every problem. Legacy `signatureBlocks`/`anchorBlocks` still parse and seal unchanged.
- A built-in placement locator in `@paradoc/render`: a dependency-light PDF text scanner (`locate`, `extractFieldsFromPdf`, `pageTextRuns`, marker encoding) that resolves signature positions in converted PDFs without a PDF rendering engine. Exported from `@paradoc/render/pdf` and re-exported by `@paradoc/sdk`.
- `prepareSeal()` on draft forms: resolves the signature map and returns the exact pre-flatten PDF it describes, with per-field provenance (`declared` | `anchor` | `marker`) and warnings, without changing the form's phase.
- `SealOptions.locate` to substitute a custom placement locator.
- The schema version `2026-08-10` adds the `SignatureSlot` layer schema; the published `2026-08-06` schemas remain available unchanged.

### Changed

- Anchor-based sealing works with pure byte converters, including `hostedSealAdapter`, with zero configuration: core locates anchor text itself in the converted PDF. Adapters that resolve placements themselves still take precedence.
- The sealing guide is rewritten around signature slots, placement strategies, and pure converters.

### Fixed

- `PdfModel` resolves indirect `/Length` stream references, so PDFs written by LibreOffice no longer lose trailing stream bytes.

### Removed

- The unused `SealingRequest.options` block (`renderer`, `format`). It was never read by any implementation.

## [0.4.0] - 2026-08-06

### Changed
- Form rendering and sealing use the built-in MIME-selected renderer by default while preserving custom renderer overrides. The CLI and integrations use the same unified renderer.
- The current schema version is `2026-08-06`; the published `2026-01-01` schemas remain available unchanged.

### Added
- `@paradoc/render`, a dependency-light renderer for text, Markdown, HTML, PDF, and DOCX layers, including template control flow, PDF AcroForm filling, overlays, inspection, page selection, and flattening.
- Recursive List fields across builders, types, schemas, validation, serialization, and rendering.
- A sealing boundary with local PDF flattening and optional adapters for non-PDF conversion.

### Removed
- The legacy `@paradoc/renderers`, `@paradoc/renderer-text`, `@paradoc/renderer-pdf`, and `@paradoc/renderer-docx` packages.
- Heavy PDF, DOCX templating, and Handlebars dependencies from the rendering and e-signing paths.

## [0.3.0] - 2026-06-19

### Added
- `@paradoc/expr`: a purpose-built, typed expression language for artifacts — a parser, an evaluator, and an artifact-aware type checker sharing one function registry. Exact-decimal arithmetic (no floating-point drift), temporal types (date, datetime, time, duration), `in` / `not in`, and null-safe access.
- `@paradoc/sessions` is now published: the deterministic, event-sourced form-completion session engine.
- Dependency-aware fill state: a single `status` ordinal (`hidden`, `optional`, `required`), transitive `blockedBy`, and DAG-ordered next-field.
- The expression engine is reachable through `@paradoc/sdk` as the `expr` namespace (`expr.check`, `expr.parse`, `expr.Decimal`).
- Documentation for `@paradoc/sessions` and `@paradoc/expr`, and the fieldset visibility cascade.

### Changed
- Artifact logic now runs on `@paradoc/expr`. A hidden fieldset hides its entire subtree, and a child's required follows its effective visibility.

### Removed
- The `expr-eval-fork` dependency.
