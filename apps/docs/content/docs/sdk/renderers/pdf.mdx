---
title: pdfRenderer
description: Fill PDF forms with AcroForm field support
---

Fill PDF forms with Paradoc's dependency-light PDF implementation. It supports
AcroForm text fields, checkboxes, dropdowns, and radio buttons with automatic
field formatting, plus coordinate-based text and image overlays.

## Example

```ts
import { p } from '@paradoc/core'
import { pdfRenderer } from '@paradoc/render/pdf'
import { createFsResolver } from '@paradoc/resolvers/fs'

const resolver = createFsResolver({ root: process.cwd() })

const form = p.form({
  name: 'w9',
  fields: {
    name: { type: 'text', label: 'Name' },
    businessName: { type: 'text', label: 'Business Name' },
    taxClassification: { type: 'enum', enum: [{ value: 'individual' }, { value: 'llc' }, { value: 'corporation' }] },
    address: { type: 'text', label: 'Address' },
    ssn: { type: 'text', label: 'SSN' }
  },
  layers: {
    pdf: {
      kind: 'file',
      mimeType: 'application/pdf',
      path: '/templates/w9-form.pdf',
      bindings: {
        // Map PDF field names to form field expressions
        'topmostSubform[0].Page1[0].f1_1[0]': 'name',
        'topmostSubform[0].Page1[0].f1_2[0]': 'businessName',
        'topmostSubform[0].Page1[0].c1_1[0]': 'taxClassification:individual',
        'topmostSubform[0].Page1[0].c1_1[1]': 'taxClassification:llc',
        'topmostSubform[0].Page1[0].f1_5[0]': 'address'
      }
    }
  },
  defaultLayer: 'pdf'
}, { resolver })

// Fill the form with data
const filled = form.fill({
  fields: {
    name: 'John Smith',
    businessName: 'Smith Consulting',
    taxClassification: 'llc',
    address: '123 Main St, New York, NY 10001'
  }
})

// The resolver was bound when the form was constructed, so every instance
// derived from it — filled included — carries it. render() doesn't take one.
const output = await filled.render({
  renderer: pdfRenderer()
})

// output is Uint8Array - write to file
fs.writeFileSync('w9-filled.pdf', output)
```

A `PdfOverlay` is either text or an image placed at `page` (one-based), `x`,
and `y` (PDF points from the bottom-left corner). A text overlay carries `text`
or a `field` path to read from the data, plus optional `fontSize`, `width`,
`height`, and `color`. Overlay text follows the same font order and failure
rules as field values, and a text overlay with a `width` fails with an
`overflow` error when its text does not fit at 6 points. An image overlay
carries `image` bytes, `mediaType` (`'image/png'` or `'image/jpeg'`), `width`,
`height`, and optional `fit`.

#### Returns

Returns a `Promise<Uint8Array>` containing the filled PDF document.

## Inspecting PDF Fields

Use `inspectAcroFormFields()` to discover field names in a PDF template:

```ts
import { inspectAcroFormFields } from '@paradoc/render/pdf'
import fs from 'fs'

const template = fs.readFileSync('form.pdf')
const fields = await inspectAcroFormFields(template)

console.log(fields)
// [
//   { name: 'f1_1', type: 'text', required: true },
//   { name: 'c1_1', type: 'checkbox', value: false },
//   { name: 'dropdown1', type: 'dropdown', value: ['Option A'] }
// ]
```

## PDF utilities

`@paradoc/render/pdf` exports dependency-light helpers for working with PDF
bytes directly.

| Function | Description |
|----------|-------------|
| `inspectPdf(pdf)` | Returns `{ pageCount, pages }`, with each page's one-based number, `width`, and `height` in PDF points |
| `flattenPdf(pdf)` | Burns AcroForm field appearances into the pages and removes the interactive controls. A PDF with no AcroForm returns unchanged |
| `selectPdfPages(pdf, pages)` | Returns a PDF with the given one-based pages, in source order. Pages must be unique positive integers that exist |
| `mergePdfs(pdfs)` | Concatenates PDFs into one, keeping every page in order. A single source returns unchanged |

```ts
import { flattenPdf, inspectPdf, mergePdfs, selectPdfPages } from '@paradoc/render/pdf'

const { pageCount } = await inspectPdf(filled)
const flat = await flattenPdf(filled)
const firstTwo = await selectPdfPages(flat, [1, 2])
const packet = await mergePdfs([firstTwo, coverLetter])
```

`mergePdfs` throws `PdfMergeError` when a source has no catalog or pages, is
encrypted, or cannot be read. Its `source` property is the zero-based index of
that source.

The same entry point exports the signature placement helpers the SDK
re-exports: `locate`, `locator`, `LocateError`, `extractFieldsFromPdf`,
`UnknownMarkerError`, and the marker `encode` and `decodeAll` functions.
`extractFieldsFromPdf` and `locate` throw `UnknownMarkerError`, naming the page,
signer, and field type code, when a marker's field type is not signature or
initials.

## Binding Syntax

PDF bindings map AcroForm field names to form field names with special syntax for complex cases:

### Simple Binding

```ts
bindings: {
  'pdfFieldName': 'formFieldName'
}
```

### Enum Checkboxes

For PDF checkboxes that represent enum values, use `:value` syntax:

```ts
bindings: {
  'checkbox_individual': 'taxType:individual',  // Check if taxType === 'individual'
  'checkbox_llc': 'taxType:llc',                // Check if taxType === 'llc'
  'checkbox_corp': 'taxType:corporation'        // Check if taxType === 'corporation'
}
```

### Split Fields

For fields split across multiple PDF inputs (like SSN), use `:partNumber` syntax:

```ts
bindings: {
  'ssn_part1': 'ssn:1',  // First part: "123" from "123-45-6789"
  'ssn_part2': 'ssn:2',  // Second part: "45"
  'ssn_part3': 'ssn:3'   // Third part: "6789"
}
```

### Combined Fields

Combine multiple form fields into one PDF field:

```ts
bindings: {
  'cityStateZip': 'city,state,zipCode'  // "San Francisco, CA, 94105"
}
```

### Nested Paths

Access nested data using dot notation:

```ts
bindings: {
  'buyer_name': 'parties.buyer.name'
}
```

### Reading bindings back

[Extraction](/sdk/artifacts/form#extracting-data-from-a-filled-pdf) reverses simple, nested, enum checkbox, and split bindings exactly. A combined binding cannot be split back, so its fields are reported as not recoverable.

## Field appearance

Filling draws each value the way the form's designer set up the field:

- **Size:** the font size in the field's default appearance, or automatic sizing when that size is zero.
- **Alignment:** left, centered, or right, from the field's quadding.
- **Color:** the color in the field's default appearance.
- **Comb:** one character per box across the field's `MaxLen` boxes, so a TIN lands one digit per box.
- **Multiline:** text wraps within the field and keeps explicit line breaks.
- **Choice:** a combo box shows the selected option's display text; a list box shows every selected value, one per line.

A value that does not fit is reduced in size, down to `MIN_FONT_SIZE` (6 points). Below that, filling fails instead of clipping the value. Checkbox and radio fields are unchanged.

## Checking bindings before filling

`validateLayers()`, `paradoc validate`, and the `validate_artifact` AI tool check each binding of a form's PDF layer to a text field before any data exists. The check builds values the bound field accepts and lays them out with the same code filling uses, in the font filling would choose: the layer's declared font, then the form's own font for the field, then Helvetica. A font supplied only at render time is not known to the check.

A text, email, uuid, or uri field is checked at its length bound: `maxLength` characters, or the length its `pattern` bounds, whichever is shorter. A uuid field without a pattern takes its 36-character canonical form. Two values of that length are laid out:

- **A typical value** is made of the repeated reference text `The quick brown fox jumps over the lazy dog ` (exported as `TYPICAL_TEXT`). It holds every lowercase letter, one capital, and word spaces at about the rate English prose has them. Its mean advance in Helvetica, 456 units per 1000, sits just above that of letter-frequency-weighted English text (441), so a box that holds it holds ordinary answers. A position the pattern constrains holds the allowed character nearest the allowed characters' mean width. If the typical value cannot fit at 6 points, it is an **error**.
- **The widest value** holds the widest character each position allows: for an open position, the widest Latin letter or digit in the font (`W` in Helvetica). If only this value cannot fit, it is a **warning**: ordinary answers fill, and an answer made mostly of wide capitals does not.

Other bindings are checked exactly, and a failure is an **error**:

- **Comb fields:** a value longer than the field's boxes (`comb-length`).
- **Split bindings** (`ssn:3`): the matching hyphen-separated part of the pattern. When the pattern does not fix where the hyphens fall, the part is bounded by the whole value's `maxLength`.
- **Enum fields:** the widest option value, since a PDF text box writes the value. **Multiselect fields:** the widest `max` option values, or all of them, joined with `, `.
- **Combined bindings:** each path's value, joined with `, `.

A bound text field with nothing bounding its length is a **warning** (`unbounded`). `validateLayers()` returns warnings in `result.warnings`; they do not fail validation. Composite parts such as `address.line1`, party values, and computed values are not checked.

The check is also exported on its own:

```ts
import { checkPdfBindingFit } from '@paradoc/render/pdf'

const issues = await checkPdfBindingFit({ template: pdfBytes, form, bindings })
// [{ field: 'amountSource', paths: ['fields.amountSource'], severity: 'error', reason: 'overflow', value: 'typical', limit: 6, length: 200, message: '...' }]
```

## Fonts

For each text value, filling uses the first font that can draw every character of the value:

1. a font supplied at render time;
2. the font the artifact's PDF layer declares;
3. the form's own embedded font for that field, when it has every glyph the value needs;
4. standard Helvetica, for Latin-1 (WinAnsi) text only.

Most official forms need no font configuration: their values are Latin-1 and fill in Helvetica. For names in Latin Extended, Greek, Cyrillic, or CJK scripts, declare a TrueType font (`.ttf`) on the PDF layer. The font is read through the same resolver as the layer's PDF, so it travels with the artifact:

```json
"pdf": {
  "kind": "file",
  "mimeType": "application/pdf",
  "path": "w-9.pdf",
  "font": { "path": "fonts/NotoSans-Regular.ttf" }
}
```

A host application can supply a font at render time, for example a licensed corporate font. It wins over the layer's font:

```ts
import { renderLayer } from '@paradoc/render'

const output = await filled.render({
  renderer: renderLayer({ pdfFont: { bytes: corporateFont, source: 'corporate.ttf' } }),
})
```

`pdfRenderer({ font })` and `renderPdf({ font, layerFont })` take the same `PdfFont`: the font's `bytes` and a `source` that errors name it by. Every font used to draw is embedded in the output, so the PDF displays the same in any viewer. Only TrueType-outline fonts are supported; an OpenType font with CFF outlines, a font collection, or a WOFF file is refused.

Filling draws one glyph per character, left to right. It does not shape text, so Arabic, Hebrew, Devanagari, Thai, and other scripts that need shaping or right-to-left ordering are refused, whatever font is available. Render documents in those scripts from a [React composition layer](/guides/react-layers).

## Errors

A value that cannot be drawn faithfully fails with `PdfFieldFillError`. It names the field (or the text overlay) and the reason:

| `reason` | When | Detail |
|---|---|---|
| `overflow` | The value does not fit at the minimum size | `limit`: the minimum size in points |
| `comb-length` | The value has more characters than the comb field has boxes | `limit`: the number of boxes |
| `missing-glyph` | No available font can draw a character | `character`: the character. Declare a font that covers it. |
| `unsupported-script` | The value is in a script that needs shaping | `script`: the script, such as `Arabic` |

A supplied or declared font that cannot be used fails with `PdfFontError`, naming its `source` and the `problem`: `unreadable`, `unsupported-format`, or `not-embeddable` (its license forbids embedding). A declared font the resolver cannot find fails the same way a missing layer file does.

```ts
import { PdfFieldFillError, PdfFontError, renderPdf } from '@paradoc/render/pdf'

try {
  await renderPdf({ template, data, bindings })
} catch (error) {
  if (error instanceof PdfFieldFillError) console.error(error.field, error.reason)
  else if (error instanceof PdfFontError) console.error(error.source, error.problem)
  else throw error
}
```

## Artifact formatting

Pass `formatter` to the artifact's `render()`, `prepareSeal()`, or `seal()` call to use the same presentation on every pass. Direct `renderPdf()` and `pdfRenderer()` also accept a formatter. Artifact context overrides the renderer default.

When the template pre-prints the currency symbol beside each money box, as IRS 1099 forms do, the layer declares it:

```json
"pdfCopyA": {
  "kind": "file",
  "mimeType": "application/pdf",
  "path": "1099-nec-A.pdf",
  "format": { "money": { "currencyDisplay": "none" } }
}
```

Every render of that layer then prints `12,000.00` instead of `$12,000.00`, with no formatter to configure. The layer's format applies over the formatter the render uses, so its locale and digits still apply; only the symbol goes. The amount keeps its currency's fraction digits. Other layers of the artifact, such as its Markdown, keep the symbol, and a layer that reuses these bindings through `bindingsFrom` declares its own `format`.

Only PDF layers take `format`, and `currencyDisplay: 'none'` is the only value. Declare the money field's `currency` too: [extraction](/sdk/artifacts/form#extracting-data-from-a-filled-pdf) reads an amount printed without a symbol in that currency.

Formatting applies to indexed fields, computed values, parties, and field overlays. Invalid values and unknown binding sources reject with field diagnostics. Checkboxes and selection controls retain their raw value identity.

Text outside Latin-1 needs a font that covers it; see [Fonts](#fonts). Without one, filling fails naming the field and the character.
