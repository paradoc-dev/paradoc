Resolvers provide a unified interface for loading file-based content (templates, assets) when rendering forms. They abstract away the underlying storage mechanism, whether in-memory, filesystem, or remote.

<Callout type="warn">
The `@paradoc/resolvers` package contains environment-specific resolvers (like filesystem) and is **not included in the SDK**. Install it separately for Node.js environments. For browser environments, use `createMemoryResolver` from `@paradoc/core`.
</Callout>

# Resolver Interface

All resolvers implement this simple interface:

```ts
interface Resolver {
  read(path: string): Promise<Uint8Array>
}
```

A resolver is bound once, when an artifact is constructed — `para.form(schema, { resolver })`, a builder's `.build({ resolver })`, or `para.load(content, { resolver })`. Every instance you derive from it afterward — every `fill`, every mutator, every render call — carries that same resolver, so you never pass it again.

# ArtifactInstanceOptions

The options object every construction entry point accepts:

```ts
interface ArtifactInstanceOptions {
  resolver?: Resolver
}
```

It's accepted by:

- `para.form(input, options?)`, `form.from(input, options?)`, `form.safeFrom(input, options?)`, and a form builder's `.build(options?)` — and the same four entry points for `document` and `checklist`.
- `load`, `loadFromObject`, `safeLoad`, and `safeLoadFromObject`, when reconstructing a form, document, or checklist. (Loading a bundle takes no `resolver`: a bundle has no file-backed layers of its own, only content entries that carry their own.)
- `runtimeFormFromJSON`, `runtimeDocumentFromJSON`, and `runtimeChecklistFromJSON`, when rebuilding a runtime (filled) instance from its JSON.

`resolver` is the only field, and it's optional: pass it only when the artifact has file-backed layers. It's bound once, at construction, and every instance you derive afterward — every `fill`, mutator, and `clone` — carries it. A render call never takes one.

Render a file-backed layer with no resolver bound, and Paradoc throws
`UnboundResolverError`, naming the layer, the path it wanted, and where to
bind one.

# Memory Resolver (Browser-Compatible)

The `createMemoryResolver` function is exported from `@paradoc/core` and works in any environment, including browsers.

```ts
import { para, createMemoryResolver } from '@paradoc/core'

const resolver = createMemoryResolver({
  contents: {
    '/templates/receipt.html': '<h1>Receipt for {{customer}}</h1>',
    '/templates/contract.docx': docxTemplateBytes,
    '/assets/logo.png': logoBytes,
  }
})

// Bind the resolver when the form is built — the form has file-based layers
const form = para.form(formSchema, { resolver })

const filled = form.fill({
  fields: { customer: 'Acme Corp' }
})

const output = await filled.render()
```

# Filesystem Resolver (Node.js Only)

<Callout type="warn">
The filesystem resolver requires Node.js and is in a separate package. Install with `npm install @paradoc/resolvers`.
</Callout>

```ts
import { createFsResolver } from '@paradoc/resolvers'

const resolver = createFsResolver({
  root: process.cwd()
})

// Reads files relative to the root directory
const bytes = await resolver.read('/templates/form.docx')
```

## Installation

```bash
npm install @paradoc/resolvers
```

<Callout type="info">
The filesystem resolver validates that all paths stay within the root directory. Attempting to access files outside the root (e.g., using `../`) will throw an error: `Path traversal detected: "..." resolves outside root directory`.
</Callout>

# Usage with File-Based Layers

Resolvers are needed when forms define file-based layers:

```ts
import { para } from '@paradoc/core'
import { createFsResolver } from '@paradoc/resolvers'

const resolver = createFsResolver({ root: process.cwd() })

const form = para.form({
  name: 'w9',
  fields: {
    name: { type: 'text' },
    taxId: { type: 'text' }
  },
  layers: {
    pdf: {
      kind: 'file',                    // File-based layer
      mimeType: 'application/pdf',
      path: '/templates/w9-form.pdf',  // Resolved via resolver
      bindings: { /* ... */ }
    }
  },
  defaultLayer: 'pdf'
}, { resolver })

const filled = form.fill({
  fields: { name: 'John Smith', taxId: '12-3456789' }
})

const output = await filled.render()
```

Render a file layer with no resolver bound and Paradoc throws
`UnboundResolverError`, naming the layer, the path it wanted, and where to
bind one.

# Inline vs File Layers

- **Inline layers** (`kind: 'inline'`) embed content directly in the form definition. No resolver needed.
- **File layers** (`kind: 'file'`) reference external files by path. A resolver must be bound when the artifact is constructed.

```ts
// Inline layer - no resolver needed
layers: {
  html: {
    kind: 'inline',
    mimeType: 'text/html',
    text: '<h1>{{title}}</h1>'
  }
}

// File layer - resolver required
layers: {
  pdf: {
    kind: 'file',
    mimeType: 'application/pdf',
    path: '/templates/form.pdf'
  }
}
```

# Custom Resolvers

Implement the `Resolver` interface for custom storage backends:

```ts
import type { Resolver } from '@paradoc/types'

// Example: HTTP resolver
function createHttpResolver(baseUrl: string): Resolver {
  return {
    async read(path: string): Promise<Uint8Array> {
      const response = await fetch(`${baseUrl}${path}`)
      if (!response.ok) {
        throw new Error(`Failed to fetch: ${path}`)
      }
      const buffer = await response.arrayBuffer()
      return new Uint8Array(buffer)
    }
  }
}

// Example: S3 resolver
function createS3Resolver(bucket: string, s3Client: S3Client): Resolver {
  return {
    async read(path: string): Promise<Uint8Array> {
      const response = await s3Client.getObject({ Bucket: bucket, Key: path })
      return new Uint8Array(await response.Body.transformToByteArray())
    }
  }
}
```
