## Artifact Builders

Artifact builders create top-level schema types that can be validated, serialized, and rendered independently.

## Available Builders

| Builder | Description | Badge |
|---------|-------------|-------|
| [document](/sdk/artifacts/document) | Static content (disclosures, pamphlets) | Design-time |
| [form](/sdk/artifacts/form) | Interactive forms with fields and parties | Design-time |
| [checklist](/sdk/artifacts/checklist) | Task lists and verification items | Design-time |
| [bundle](/sdk/artifacts/bundle) | Collection of multiple artifacts | Design-time |

## Common Features

All artifact builders share common functionality:

### Static Methods

- `.from(input)` - Parse unknown input, throws on error
- `.safeFrom(input)` - Parse unknown input, returns result object

### Instance Methods

- `.validate()` - Validate the schema definition
- `.isValid()` - Check if schema is valid
- `.toJSON()` - Serialize to JSON, with the current dated `$schema`
- `.toYAML()` - Serialize to YAML, with the current dated `$schema`
- `.clone()` - Deep clone the instance

### Validating templates

`validate(artifact)` checks every template expression in inline text layers along with the schema and logic. File-backed text and DOCX layers are read through a resolver, so they are checked by `validateLayers`:

```ts
import { validateLayers } from '@paradoc/sdk'
import { createFsResolver } from '@paradoc/resolvers/fs'

const result = await validateLayers(artifact, { resolver: createFsResolver({ root: '.' }) })
// result.issues: 'Template error at layer "markdown", line 12, column 7 in {{fields.amount}}: ...'
```

For a form, `validateLayers` also checks that values a PDF layer binding accepts can fill its PDF text field: a typical value at the field's `maxLength` or `pattern` length that is too wide for its box, an option value too wide for its box, or a value too long for its comb boxes is an error. A value that overflows only when made of the widest letters, and a bound text field with no length bound, are returned in `result.warnings`, which do not fail validation. See [Checking bindings before filling](/sdk/renderers/pdf#checking-bindings-before-filling).

### Schema versions

An artifact built with the SDK is always the current [schema version](/schemas#schema-versions). `load()` and `safeLoad()` refuse file content written for another version with a `SchemaVersionError`, as the [loading rules](/schemas#loading-rules) describe. To bring an artifact written for an earlier version up to date, use `migrateArtifact` for a parsed object or `migrateArtifactSource` for file content. Both apply the migration steps in order, validate the result, and fail with `SchemaMigrationError` instead of guessing. The [`paradoc migrate`](/cli/commands/migrate) command uses them.

```ts
import { migrateArtifactSource } from '@paradoc/sdk'

const result = migrateArtifactSource(yamlText, { format: 'yaml' })
if (result.status === 'migrated') {
  console.log(`${result.from} → ${result.to}`)
  // result.content is the rewritten YAML, comments kept
}
```

### Instance Properties

- `_data` - Raw artifact data
- `kind` - Artifact type discriminator
- `name` - Artifact name
- `version` - Semantic version
- `instructions` - Domain/compliance reference content ([ContentRef](/schemas/artifacts/shared/content-ref))
- `agentInstructions` - LLM/agent presentation guidance ([ContentRef](/schemas/artifacts/shared/content-ref))
