The Paradoc MCP server lets AI assistants validate, fill, render, and browse artifacts over the [Model Context Protocol](https://modelcontextprotocol.io). It is a hosted Paradoc Platform service, so there is nothing to install. You need a Platform account and authenticate through OAuth or an API key.

## Endpoints

| Endpoint | URL |
|----------|-----|
| MCP | `https://mcp.paradoc.dev/mcp` |
| Health check | `https://mcp.paradoc.dev/health` |
| Service info | `https://mcp.paradoc.dev/` |
| OAuth protected-resource metadata | `https://mcp.paradoc.dev/.well-known/oauth-protected-resource` |

## Authentication

The server accepts two credentials:

- **OAuth bearer token.** Interactive clients sign in through Paradoc's authorization server and send `Authorization: Bearer <token>`. The token must be scoped to an organization. A token with no organization is treated as no credential.
- **API key.** Headless clients send a Paradoc API key in the `x-api-key` header.

A request to `/mcp` without a valid credential gets `401 Unauthorized` with a `WWW-Authenticate: Bearer resource_metadata="https://mcp.paradoc.dev/.well-known/oauth-protected-resource"` header. OAuth-capable clients read that metadata to find the authorization server and start sign-in.

If the service cannot verify an API key, it returns `503 Service Unavailable`; retry that request later. A `POST /mcp` request without the client IP metadata required for rate limiting returns `400 Bad Request`.

## Connecting

<Tabs items={['OAuth', 'API key']} groupId="mcp-auth" persist>
  <Tab value="OAuth">
    Add the server by URL in any MCP client that supports OAuth. The client runs the sign-in flow on first connect. For example, in Claude Code:

    ```bash
    claude mcp add --transport http paradoc https://mcp.paradoc.dev/mcp
    ```

    Then run `/mcp` in Claude Code and choose **Authenticate**.
  </Tab>
  <Tab value="API key">
    Send your key in the `x-api-key` header. For example, in a project's `.mcp.json`:

    ```json
    {
      "mcpServers": {
        "paradoc": {
          "type": "http",
          "url": "https://mcp.paradoc.dev/mcp",
          "headers": {
            "x-api-key": "${PARADOC_API_KEY}"
          }
        }
      }
    }
    ```
  </Tab>
</Tabs>

Once the session is authenticated, the client sees the tools below.

## Tools

### Core

- [`validate`](/mcp/tools/validate) - Validate an artifact against the Paradoc schema
- [`fill`](/mcp/tools/fill) - Fill a form or checklist with data and report whether it is complete

### Rendering

- [`render`](/mcp/tools/render) - Render a form from a verified registry as text, PDF, or DOCX

### Registry

- [`list_artifacts`](/mcp/tools/list-artifacts) - Browse artifacts ranked by popularity
- [`get_artifact`](/mcp/tools/get-artifact) - Get the full artifact JSON and metadata
- [`list_registries`](/mcp/tools/list-registries) - List registries with artifact counts and install stats
- [`get_registry`](/mcp/tools/get-registry) - Get details for a specific registry and its artifacts
- [`search`](/mcp/tools/search) - Search artifacts and registries by keyword

### Platform tools

The same session also exposes the Paradoc platform's execution, e-signature, and payment tools (for example `extract`, `seal`, `create_envelope`, and `create_payment`). They act on your organization's account and are documented with the platform API, not here.

## Rate limits

Only `POST /mcp` is rate-limited, per client IP, and the limit applies before the credential check. The production server (`mcp.paradoc.dev`) allows 2 requests per 60-second window (about 120 per hour). The development server (`mcp-dev.paradoc.dev`) allows 60 requests per 60-second window. A request over the limit gets `429`.
