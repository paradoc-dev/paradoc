Creates a progressive draft from supplied data. Supplied values validate immediately while omitted required values remain open. The response reports `accepted` for the supplied patch and `complete` for full readiness. Pass the full artifact JSON and a data object. Call `get_artifact` first to inspect field and party definitions.

The tool works only on the artifact you pass in and calls no registry or API. Like every tool on this server, it needs an [authenticated session](/mcp#authentication).

<Callout type="info">
  Only forms and checklists support filling. Passing a document or bundle will return an error.
</Callout>

## Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `artifact` | `object` | Yes | The Paradoc artifact (form or checklist) definition |
| `data` | `object` | Yes | Data to fill. Fields go under `"fields"` key: `{ fields: { fieldId: value } }`. Parties go under their party ID: `{ partyId: { id, name, ... } }`. |

## Response

| Field | Type | Description |
|-------|------|-------------|
| `accepted` | `boolean` | Whether every supplied value was accepted |
| `complete` | `boolean` | Whether the artifact is ready for its final transition (every required value present and valid) |
| `artifactKind` | `string` | Detected kind: `form` or `checklist` |
| `data` | `object` | The accepted values with defaults applied (when `accepted` is `true`) |
| `errors` | `array` | Rejected values, each with `field` and `message` |
| `error` | `string` | Error message if filling could not be performed (for example, the artifact is not a form or checklist) |

## Examples

### Accepted patch

```json
// Request
{
  "artifact": { "kind": "form", "..." : "..." },
  "data": { "fields": { "firstName": "Jane", "age": 30 } }
}

// Response
{
  "accepted": true,
  "complete": false,
  "artifactKind": "form",
  "data": { "firstName": "Jane", "age": 30 }
}
```

The supplied values were accepted, but `complete` is `false` because other required fields are still open. The `data` field contains the accepted values with any defaults the artifact defines. The tool keeps no state between calls: to continue the draft, call it again with every value so far. `complete` turns `true` once every required value is present and valid.

### Rejected value

```json
// Request
{
  "artifact": { "kind": "form", "..." : "..." },
  "data": { "fields": { "firstName": "Jane", "age": "thirty" } }
}

// Response
{
  "accepted": false,
  "complete": false,
  "artifactKind": "form",
  "errors": [
    { "field": "age", "message": "Expected number, received string" }
  ]
}
```

Each error names the `field` and gives a `message` describing why the value was rejected.
