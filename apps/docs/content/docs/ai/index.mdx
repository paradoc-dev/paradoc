Paradoc gives AI agents ten document tools. With them an agent can find an artifact in a registry, inspect it, validate it, fill it, render it, and read a filled PDF form back into data.

## Pick a route

| You want | Use |
|----------|-----|
| An agent you build to call the tools | The AI tool packages: install the adapter for your framework, below |
| A coding agent, such as Claude Code, to write Paradoc code with you | [Agent skills](/ai/skills) |
| A hosted tool server that any MCP client connects to | The hosted MCP server at `mcp.paradoc.dev`. See [how it differs](#differences-from-the-mcp-server). |

## Add the tools to your agent

| Package | Use it for | Install |
|---------|------------|---------|
| [`@paradoc/ai-sdk`](/ai/ai-sdk) | Vercel AI SDK 7 | `npm install @paradoc/ai-sdk ai zod` |
| [`@paradoc/tanstack-ai`](/ai/tanstack-ai) | TanStack AI | `npm install @paradoc/tanstack-ai@0.7.0 @tanstack/ai@0.53.0 @tanstack/ai-openai@0.22.5 zod` |
| [`@paradoc/mastra`](/ai/mastra) | Mastra | `npm install @paradoc/mastra @mastra/core zod` |
| [`@paradoc/ai-tools`](/ai/other-frameworks) | Any other framework, or plain code | `npm install @paradoc/ai-tools` |

Each adapter wraps `@paradoc/ai-tools`, so every adapter exposes the same tools with the same schemas.

    ```typescript
    import { chat } from "@tanstack/ai"
    import { openaiText } from "@tanstack/ai-openai"

      adapter: openaiText("gpt-4o"),
      messages: [{ role: "user", content: "Fill the pet addendum for my dog Rex" }],
    ```

### The tools

Every adapter exposes the same ten tools, named in snake_case: `get_registry`, `get_artifact`, `inspect_artifact`, `validate_artifact`, `validate_input`, `fill`, `get_fill_state`, `update_fill`, `render`, and `extract`. The [tool reference](/ai-tools) gives the inputs and outputs of each one.

Every adapter takes the same options, such as a default registry and an origin allowlist. See [Configuration](/ai-tools/api#configuration).

## Differences from the MCP server

| | MCP server | AI packages |
|---|---|---|
| **Runs where** | Hosted at `mcp.paradoc.dev` | Your own application |
| **Protocol** | Model Context Protocol | Your framework's tool API (AI SDK, TanStack AI, Mastra) |
| **Registry lookup** | DB-backed registry IDs | Direct registry URLs |
| **Render output** | Short-link URL or inline | Inline only |
| **Auth** | Every `/mcp` request needs an OAuth bearer token scoped to an organization, or an `x-api-key` header. An OAuth connection is granted test, live, or both modes in the console; with both, each platform call names its mode. | Your config (`fetch`, API keys) |
| **Tools only here** | `list_artifacts`, `list_registries`, `search`, and platform tools for e-signature envelopes, payments, and extraction jobs | `inspect_artifact`, `validate_input`, `get_fill_state`, `update_fill` |
| **Extraction** | The platform `extract` tool runs hosted extraction jobs, including scanned and flattened documents | [`extract`](/ai-tools/extract) reads the fields of a fillable PDF in your own process, with no service call |
